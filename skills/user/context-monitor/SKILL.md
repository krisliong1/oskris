# Context Monitor — 上下文监控与管理

## 核心发现（研究支撑）

Context Window 性能降级不是在 100% 时才发生，而是在 20-40% 就开始。降级是悬崖式非线性的，不是缓慢的。

### 研究来源

1. **Chroma Research (2025)** — "Context Rot" 报告，测试 18 个 LLM。性能随 input 长度持续降级，有突然的悬崖式下降点。来源：https://research.trychroma.com/context-rot
2. **arXiv (2025-12)** — "Context Discipline and Performance Correlation"。KV cache 增长导致非线性性能降级。来源：https://arxiv.org/abs/2601.11564
3. **arXiv (2025-09)** — "Maximum Effective Context Window"。大多数模型在 1000 tokens 就开始准确率下降，实际有效窗口 vs 理论最大窗口差距可达 99%。来源：https://arxiv.org/abs/2509.21361
4. **Claude Code Ultimate Guide** — 200K 窗口中实际可用约 140-150K，系统在 75-92% 自动 compaction，建议 70% 就主动 compact。
5. **Factory.ai** — "models do not use their context uniformly"，性能随 context 增长越来越不可靠。

### 降级阶段

```
0-20%    ✅ 最佳性能区 — 完全正常
20-40%   ⚠️ 早期降级 — 细微质量下降，开始遗漏细节
40-60%   🟡 明显降级 — 回复变短、推理变浅、容易遗漏要求
60-80%   🔴 严重降级 — 忘记上下文、重复内容、推理错误增多
80-100%  ❌ 危险区 — 基本不可靠，必须立即处理
```

## 环境自动检测

Claude 在每次对话中自动判断用户当前使用的环境，并切换对应策略：

### 检测方法

```
Claude.ai 网页端特征：
- 能访问 /mnt/skills/user/
- 能使用 bash_tool、view 等工具
- 用户消息通常较完整

Claude.ai 手机端特征：
- 同上，但用户消息通常更简短、口语化
- 可能不方便看长代码输出
- 优先简洁回复

Claude Code 终端特征：
- 能访问项目目录（如 /home/user/project/）
- 有 .claude/ 目录
- 用户可执行 /compact、/clear、/resume 等命令
- 用户消息通常包含技术操作指令
```

### 策略切换

| 操作 | Claude.ai（网页/手机） | Claude Code（终端） |
|------|----------------------|-------------------|
| **监控方式** | Claude 自我估算轮次和 token | /context 命令查看精确数据 |
| **降级预防** | 建议用户开新对话 | /compact 或 /clear 重置 |
| **信息保持** | 总结关键信息让用户带到新对话 | 保存到 SCRATCHPAD.md/plan.md 后 /clear |
| **提醒格式** | 简洁一行提示 | 详细操作命令 |
| **30% 阈值** | "建议开新对话继续" | "建议执行 /compact" |
| **50% 阈值** | "强烈建议开新对话" | "建议 /clear 后粘贴关键信息" |

## 主动监控机制

### Claude 必须执行的监控

**每 10 轮对话主动报告**：

Claude.ai 环境：
```
📊 Context 估计：约 XX%（第 N 轮）| 状态：[✅/⚠️/🔴] | 建议：[继续/考虑开新对话/立即开新对话]
```

Claude Code 环境：
```
📊 Context 估计：约 XX% | 建议：/compact 或 /clear
```

**检测到降级症状时立即提醒**（不等到第 10 轮）。

**任务复杂度高时提前提醒**（代码生成、多步骤操作、读取大文件）。

### Token 消耗估算表

```
每轮对话平均消耗：
- 简单问答：500-1,500 tokens
- 代码生成/分析：2,000-8,000 tokens
- 文件操作（bash_tool）：3,000-15,000 tokens
- 长文档分析：5,000-20,000 tokens
- 大量工具调用：10,000-30,000 tokens

估算公式：
预估使用量 = Σ(每轮估计消耗)
预估百分比 = 预估使用量 / 200,000 × 100%
```

### 轮次-百分比快速参考

```
轮次        预估 Context    状态        建议
──────────────────────────────────────────────────
1-5轮      ~5-15%         ✅ 最佳     放心使用
5-10轮     ~15-30%        ✅ 良好     正常使用
10-15轮    ~30-45%        ⚠️ 注意     提高效率，精简回复
15-20轮    ~45-60%        🟡 降级     开始考虑开新对话
20-30轮    ~60-80%        🔴 危险     强烈建议开新对话
30+轮      ~80%+          ❌ 严重     必须开新对话

注意：使用工具（bash、浏览器等）会消耗更多 token，实际轮次可能更少。
```

### 降级症状自检

Claude 在每次回复前快速自检：

```
早期（20-40%）：回复开始变短？遗漏用户部分要求？不再主动引用之前细节？
中期（40-60%）：开始重复说过的内容？推理步骤减少？忘记用户偏好？
晚期（60-80%）：工具使用出错增多？不能维持多步骤任务？
危险（80%+）：完全忘记之前上下文？给出矛盾回复？
```

## 管理策略

### 策略 1：作用域对话（两个环境通用）

**原则**：一个对话 = 一个功能/任务。

正确做法：对话 1 做认证系统，对话 2 做数据库，对话 3 做邮件功能。

错误做法：一个对话里做认证 + 数据库 + UI + 部署 + bug 修复。

**何时开新对话**：开始新功能、切换不相关任务、context > 30%、质量明显下降。

### 策略 2：外部记忆文件（Claude Code 专用）

在 Claude Code 中，使用项目文件持久化信息：

**SCRATCHPAD.md**：工作笔记、临时想法、当前进度、待办事项。

**plan.md**：项目计划、架构决策、实现步骤。

好处：跨会话持久化、不占用对话上下文、可版本控制。用 /clear 重置后读取这些文件即可恢复。

### 策略 3：复制粘贴重置法（Claude Code 专用）

当 context > 40% 或质量下降时：
1. 复制关键代码片段、重要决策、错误消息
2. `/compact` 获得对话总结
3. `/clear` 完全重置
4. 粘贴回关键信息 + 总结

结果：全新 context（质量恢复）+ 保留关键信息。

**重要**：compacting 不能恢复已降级的质量。在质量降级前 compact，不是降级后。

### 策略 4：开新对话（Claude.ai 专用）

在 claude.ai 中没有 /compact、/clear 命令，主要的重置方式是开新对话。

当 Claude 建议开新对话时，会：
1. 总结当前对话的关键信息（3-5 行）
2. 列出待办事项
3. 告诉用户在新对话中说什么可以恢复上下文

示例提醒：
```
⚠️ 当前对话约 40%，质量可能开始降级。

建议开新对话，在新对话中说：
"继续做 XXX 项目，上次完成了 A 和 B，待办是 C"

这样我可以在新鲜的 context 中以最佳状态继续。
```

### 策略 5：精简回复（两个环境通用）

当 context > 30% 时自动切换到精简模式：
- 减少不必要的解释和格式
- 代码只改变的部分，不重复完整文件
- 回复直奔主题

## Claude Code 专用命令参考

```bash
/context          # 查看当前 context 使用量
/compact          # 总结对话，减少 context
/clear            # 完全清空对话 context
/resume           # 恢复之前的会话
claude --continue # 继续最近的对话
claude --resume   # 会话选择器
```

**行动阈值（Claude Code）**：
- < 20%：安全继续
- 20-30%：注意，开始规划清理
- 30-40%：准备 compact
- 40-60%：执行 compact 或复制粘贴重置法
- 60%+：立即 /clear

## MCP 上下文优化（Claude Code 专用）

**问题**：MCP 服务器工具定义会占用大量 context（4 个 MCP = ~67,000 tokens）。

**解决方案**：Tool Search 功能（Sonnet 4+ / Opus 4+），动态按需加载工具而非预加载全部。

```bash
ENABLE_TOOL_SEARCH=auto claude        # 自动模式（默认）
ENABLE_TOOL_SEARCH=auto:5 claude      # 5% 阈值触发
ENABLE_TOOL_SEARCH=false claude       # 禁用
```

效果：从 ~51,000 tokens 降至 ~8,500 tokens（减少 83%+）。

## 核心原则

```
❌ 错误认知：Context 到 100% 才有问题
✅ 正确认知：20-40% 就开始降级，是渐进式然后悬崖式的

❌ 错误做法：一直在同一个对话中工作到极限
✅ 正确做法：主动监控，提前预防，适时切换

❌ 错误做法：等用户发现质量下降才处理
✅ 正确做法：主动提醒用户，在降级前就采取行动

❌ 错误做法：claude.ai 和 Claude Code 用相同的管理方式
✅ 正确做法：检测环境，自动切换策略
```
