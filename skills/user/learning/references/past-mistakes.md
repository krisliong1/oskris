# 失败案例库 — Past Mistakes

Claude 实际犯过的错误记录。每次被用户纠正后必须更新此文件。
新对话的 Claude 在学习前应先读此文件，避免重复犯错。

## 更新规则
1. 用户纠正错误后，立刻添加新记录
2. 先检查此文件是否存在（不存在就创建）
3. 添加后推送 GitHub
4. 格式：日期 | 错误 | Claude以为 | 真实情况 | 后果 | 教训

---

## 错误记录

### 2026-02-17 | Free plan 功能判断错误
- **Claude以为**: Free plan 没有 web search
- **真实情况**: Anthropic 已经全面开放 web search 给 Free plan 用户
- **后果**: 基于错误假设设计了整个 learning skill 的方案，区分了"有/没有 web search"的场景
- **教训**: 不要凭训练数据猜测任何平台的功能，包括 Claude 自己的功能。必须搜索确认

### 2026-02-16 | 文件操作：盲目创建新文件
- **Claude以为**: 直接创建文件最快
- **真实情况**: 应该先检查文件是否存在，存在就用 str_replace 修改
- **后果**: 大量重复文件，项目目录混乱
- **教训**: 操作文件前永远先检查。用户说了有文件就绝对不要再创建

### 2026-02-16 | 角色判断错误：建议用户学习
- **Claude以为**: 用户需要"零成本启动方案"和"学习路线图"
- **真实情况**: 用户说"是你学不是我学"，用户要的是 Claude 学完直接干活
- **后果**: 浪费用户时间给了不需要的建议
- **教训**: 分清楚谁是学习者。用户有 Claude 了，Claude 学完直接执行

### 2026-02-16 | Hostinger API 未使用
- **Claude以为**: 手动操作 VPS 就行
- **真实情况**: 有 API token 应该用 API 自动化
- **后果**: 手动操作效率低，不可复现
- **教训**: 有自动化工具就用自动化，手动是最后手段

### 2026-02-16 | 存储不通知用户
- **Claude以为**: 默默存储不打扰用户
- **真实情况**: 用户要求每步都告诉他进度
- **后果**: 用户不知道发生了什么，觉得 Claude 没做事
- **教训**: 永远透明化，每步告诉用户

### 2026-02-16 | 凭训练数据回答 Claude 自身功能
- **Claude以为**: 自己知道自己有什么功能
- **真实情况**: Claude 的功能经常更新，训练数据跟不上
- **后果**: 给出过时或错误的功能说明
- **教训**: 关于自身功能也必须搜索确认

## 高频错误模式总结

1. **自信偏差**: 觉得自己知道 → 实际已过时 → 搜索可避免
2. **默认行为优先**: 规则写了但不执行 → 需要在具体场景精确触发
3. **新对话失忆**: 上次犯的错这次又犯 → 读此文件可避免
4. **理论大于行动**: 给建议而不干活 → 学完直接执行
