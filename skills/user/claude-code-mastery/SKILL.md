# Claude Code Mastery Skill

## Trigger
Use this skill when:
- Working with Claude Code (terminal-based AI coding assistant)
- Need to optimize Claude Code workflow
- Planning complex coding tasks
- Managing context in Claude Code sessions
- User mentions Claude Code, CLAUDE.md, Plan Mode, MCP, or headless mode

## Core Philosophy

**来自 7 年资深工程师的教训（Amazon/Disney/Capital One）**:

> "10/10 次，Plan Mode 的输出远胜于直接开始输入"

**基本原则**:
```
思考优先 → 计划 → 执行
不是: 输入 → 希望最好
```

## 核心技能 (10 个关键点)

### 1. 先思考，再输入 (Think First)

**永远不要**:
- ❌ 看到 Claude Code 就开始说话
- ❌ 直接输入需求
- ❌ 期待 Claude 自己搞定

**永远这样做**:
1. ✅ 思考架构
2. ✅ 规划系统设计
3. ✅ 考虑权衡
4. ✅ 使用 Plan Mode（Shift+Tab 两次）
5. ✅ 花 5 分钟规划 = 节省数小时调试

**对于新手**:
```
与 Claude/ChatGPT 深度对话:
1. 描述你想构建什么
2. 询问各种系统设计选项
3. 双向提问（不是单向）
4. 共同确定解决方案
```

---

### 2. Plan Mode = 你的秘密武器

**如何进入**:
```
Shift + Tab (第一次) = Auto-Accept Mode (⏵⏵)
Shift + Tab (第二次) = Plan Mode (⏸)
```

**Plan Mode 能做什么**:
- ✅ 读取文件和代码
- ✅ 搜索和分析
- ✅ 部署 subagents 分析架构
- ✅ 获取 web 内容
- ✅ 读写任务
- ✅ 询问澄清问题

**Plan Mode 不能做什么**:
- ❌ 创建文件
- ❌ 编辑文件
- ❌ 删除文件
- ❌ 运行修改命令
- ❌ 安装包

**何时使用**:
- 多文件实现
- 代码探索
- 复杂变更前
- 需要深度思考的架构决策

**工作流**:
```
1. Plan Mode 规划和架构（使用 Opus）
2. 审查并批准计划
3. 切换到 Sonnet 执行（Shift+Tab）
```

### 3. CLAUDE.md - 你的杠杆点

**是什么**:
- 每次会话开始，Claude 第一件事读取的文件
- 像给 Claude 的"入职培训"
- 影响每一次交互

**黄金法则**:

#### 规则 1: 保持简短 (150-200 指令限制)
```
Claude 可靠遵循: 150-200 条指令
系统提示占用: ~50 条
你的空间: ~100-150 条

太长 = Claude 随机忽略内容
```

#### 规则 2: 项目特定，不要泛泛而谈
```
❌ 不要: "components 文件夹存放组件"
✅ 要: "运行 npm run dev:custom 启动开发服务器（不是 npm run dev）"
```

#### 规则 3: 说"为什么"，不只是"什么"
```
❌ 弱: "使用 TypeScript strict mode"

✅ 强: "使用 TypeScript strict mode，
因为我们在生产环境遇到过 implicit any 类型导致的 bug"
```

**为什么有效**: 给出原因 → Claude 做出更好的判断

#### 规则 4: 持续更新
```
按 # 键 = Claude 自动添加到 CLAUDE.md

如果你纠正 Claude 同样的事两次
→ 应该写进 CLAUDE.md
```

**质量标准**:
```
❌ 糟糕 CLAUDE.md = 给新员工的文档
✅ 优秀 CLAUDE.md = 假设明天失忆给自己的笔记
```

### 4. Context Window 管理（关键！）

**震惊的真相**:
```
Opus 4.5 = 200,000 tokens 上下文
但质量在 20-40% 使用时就开始降级！
不是 100%！
```

**为什么 Compacting 救不了你**:
- 如果已经降级，Compacting 不能恢复质量
- Compacting 不是魔法

**累积的东西**:
- 每条消息
- 每个读取的文件
- 每段生成的代码
- 每个工具结果

---

### 5. 管理上下文的 4 个技巧

#### 技巧 1: 作用域对话
```
一个对话 = 一个功能/任务

❌ 错误: 同一对话构建认证 + 重构数据库
✅ 正确: 两个独立对话
```

#### 技巧 2: 外部记忆
创建持久化文件:
```
SCRATCHPAD.md - 工作笔记
plan.md - 项目计划

好处:
- 跨会话持久化
- 明天继续 → 读取文件 → 立即恢复
```

**高级**: 把这些放在层级顶部，所有任务都能用

#### 技巧 3: 复制粘贴重置法（强大！）
```
1. 复制终端所有重要内容
2. 运行 /compact 获取总结
3. 运行 /clear 完全清空上下文
4. 粘贴回重要信息

结果: 全新上下文 + 保留关键信息
```

#### 技巧 4: 知道何时清空
```
对话跑偏？ → /clear
累积无关上下文？ → /clear

重要: Claude 仍有 CLAUDE.md
不会丢失项目上下文

9/10 次，clear 比不 clear 更好（反直觉但真实）
```

### 6. 架构比一切都重要

**核心警告**:
> "只给输出不给过程 = 给 AI 巨大的发挥空间 = AI 代码的问题"

**对比示例**:

❌ **模糊（会得到过度工程化的垃圾）**:
```
"给我构建一个认证系统"
```

✅ **具体（会得到你想要的）**:
```
"使用现有 User 模型构建邮箱/密码认证，
会话存储在 Redis 中，24小时过期，
添加中间件保护 /api/protected 下的所有路由"
```

**规律**:
```
模糊 = AI 自由发挥 = 可能很糟糕
具体 = 明确约束 = 精准输出
```

### 7. 提示工程 (Prompt Engineering)

**核心真理**:
```
人们花数周学习框架
零时间学习如何与生成代码的东西沟通

提示 = 沟通
清晰 > 模糊，每次都是
```

#### 方法 1: 具体说明
```
具体 > 模糊
约束 > 开放式
示例 > 描述
```

#### 方法 2: 告诉它不要做什么
**Claude 4.5 倾向**:
- 过度工程化
- 额外文件
- 不必要的抽象

**解决**:
```
"保持简单。
不要添加我没要求的抽象。
如果可能，一个文件搞定。"
```

**重要**: 始终交叉检查 Claude 的输出

#### 方法 3: 给出为什么
```
"这需要快，因为每个请求都运行它"
→ 改变 Claude 处理问题的方式

"这是原型，我们会扔掉"
→ 改变权衡考量
```

**真相**: Claude 无法读心

### 8. 糟糕输入 = 糟糕输出

**现实检查**:
```
❌ "Claude 不够聪明"
❌ "我需要更好的模型"

✅ 真相: 你的提示很烂
```

**如果用 Opus 4.5 得到糟糕结果**:
→ 你的输入和提示很烂，句号

**修复方法** (提升 3 个技能):
1. 如何写提示（具体、约束、示例）
2. 如何构建请求（分解、先架构、审查迭代）
3. 如何提供上下文（Claude 需要知道什么？）

### 9. 模型选择（Sonnet vs Opus）

#### Sonnet（更快更便宜）
**适合**:
- ✅ 执行任务，路径清晰
- ✅ 写样板代码
- ✅ 基于特定计划重构
- ✅ 实现已做架构决策的功能

#### Opus（更慢更贵）
**适合**:
- ✅ 复杂推理
- ✅ 规划
- ✅ 深度思考权衡

**推荐工作流**:
```
1. Opus 规划和架构（Plan Mode）
2. Shift+Tab 切换到 Sonnet 实现
3. CLAUDE.md 确保两个模型在相同约束下
```

### 10. 当 Claude 卡住时

**症状**:
- 陷入循环
- 尝试同一件事 → 失败 → 再试 → 失败
- 自信但完全错误的实现

**❌ 本能但错误的反应**:
```
更多指令
更多纠正
更多上下文
```

**✅ 正确做法**: 改变方法

#### 解锁技巧:

**1. 清空对话**
```bash
/clear
```

**2. 简化任务**
```
复杂任务挣扎 → 分解成小块
每块工作后再组合

注意: 如果 Claude 在复杂任务上挣扎，
说明你的 Plan Mode 不够充分
```

**3. 展示而非告诉**
```
Claude 误解 → 写个最小示例
"这是输出应该的样子。
现在对其余部分应用这个模式。"

Claude 超级擅长理解好的示例
```

**4. 重新框架**
```
"实现为状态机" vs "处理这些转换"

不同角度可以解锁进展
```

**元技能**: 早期识别循环
```
解释同一件事 3 次 + Claude 还不明白
→ 更多解释无用
→ 改变某些东西
```

## MCP (Model Context Protocol)

**是什么**:
- 让 Claude 连接外部服务的开放标准
- 像 AI 的 USB-C 接口

**能连接什么**:
- Slack, GitHub, 数据库, APIs
- Google Calendar, Notion
- Figma 设计
- 3D 软件（Blender）

**何时使用**:
```
发现自己不断从某处复制信息到 Claude
→ 可能有 MCP server 能自动完成
```

**MCP Tool Search (2026 新功能)**:
- 自动延迟加载
- 减少 MCP 上下文使用 **95%**
- 从 51K tokens → 8.5K tokens

**配置**:
```bash
# 添加 MCP server
claude mcp add server-name \
  -e API_KEY=your-key \
  -- npx @package/server

# 查看可用工具
在 Claude 中: "What MCP tools are available?"
```

## Hooks 系统

**是什么**:
- Claude 修改前/后自动运行代码

**示例**:
```
Prettier → 每个 Claude 接触的文件自动格式化
类型检查 → 每次编辑后自动运行
```

**好处**:
- 立即捕获问题
- 不让问题堆积
- 帮助移除技术债务

**高级用法**:
```
每 1000 行后设置清理 hook
→ 持续保持代码质量
→ Claude 审查 PR 时很有用
```

## Headless Mode（构建系统的关键）

**是什么**:
```bash
claude -p "你的提示"

-p flag = headless mode
运行提示 + 输出结果
不进入交互界面
```

**可能性**:
- 脚本化 Claude
- 输出到其他工具
- 与 bash 命令链接
- 整合到自动化工作流

**企业应用**:
- 自动 PR 审查
- 自动支持工单响应
- 自动日志和文档更新

**改进飞轮**:
```
1. Claude 犯错
2. 审查日志
3. 改进 CLAUDE.md 或工具
4. Claude 下次更好
→ 持续复合改进
```

## 工作流检查清单

### 开始新任务前:
- [ ] 进入 Plan Mode (Shift+Tab 两次)
- [ ] 检查 CLAUDE.md 是否最新
- [ ] 创建/更新 SCRATCHPAD.md 或 plan.md
- [ ] 考虑这个任务是否需要新对话

### 任务执行中:
- [ ] 监控上下文使用（不要超过 30%）

- [ ] 是否陷入循环？（解释 3 次仍不明白）
- [ ] 尝试重新框架问题
- [ ] 考虑 /clear 重新开始

### 任务完成后:
- [ ] 更新 CLAUDE.md（按 # 键）
- [ ] 审查输出质量
