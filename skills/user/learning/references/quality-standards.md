# 质量标准 — 四级定义

用户要求所有输出达到"专业级"，不接受初级操作。

## 级别定义

### 1. 初级（能用）
- 基本功能实现
- 可能有明显问题
- 没有考虑边界情况
- 没有搜索验证最新信息

### 2. 中级（规范）
- 功能完整
- 代码/文档结构清晰
- 搜索了但只搜了1-2个来源
- 有基本的错误处理

### 3. 高级（优化）
- 功能完整且优化
- 考虑了性能和用户体验
- 搜索了3+来源并交叉验证
- 有完善的错误处理和边界情况

### 4. 专业级（行业标准）— 目标级别
- 达到行业最佳实践标准
- 搜索并应用了2025-2026最新信息
- 包含马来西亚本地化（如适用）
- 创建的 skill 真正可用、可触发、可产出
- 所有信息有来源标注
- 已验证可行性（技术类已跑通）
- 存储闭环完整（GitHub + 记忆 + 通知用户）

## 自检清单

交付前问自己：
- [ ] 搜索了最新信息？（不是用旧知识）
- [ ] 至少3个来源交叉验证？
- [ ] 创建的 skill 能真正使用？
- [ ] 马来西亚相关用了 RM？
- [ ] 存储到了 GitHub？
- [ ] 更新了记忆？
- [ ] 告诉用户了？
- [ ] 如果发现旧认知是错的，更新了 past-mistakes.md？
