# Context Management Skill

## Trigger
Use this skill when:
- Working with long conversations
- Context window approaching limits
- Claude's responses degrade in quality
- Need to preserve important information across sessions
- Managing multiple related tasks

## 核心原则

**震惊的真相**:
```
Opus 4.5 = 200,000 tokens 上下文
但质量在 20-40% 时就开始降级！

不是在 100% 时才降级
是在 20-40% 时！
```

**为什么重要**:
- Compacting 不能恢复已降级的质量
- 累积的上下文会让 Claude "变笨"
- 主动管理 > 被动反应

---

## 上下文累积的来源

**所有这些都占用上下文**:
1. 每条用户消息
2. 每条 Claude 响应
3. 每个读取的文件
4. 每段生成的代码
5. 每个工具调用结果
6. 每个 MCP 工具定义
7. 错误消息和调试输出

**累积速度**:
```
简单对话: 慢速累积
复杂编码任务: 快速累积
多 MCP 服务器: 极快累积
```

---

## 管理策略（4 个核心技巧）

### 技巧 1: 作用域对话

**原则**:
```
一个对话 = 一个功能/任务
```

**正确示例**:
```
对话 1: 构建认证系统
对话 2: 重构数据库层
对话 3: 添加邮件功能
```

**错误示例**:
```
❌ 一个对话:
   - 构建认证
   - 重构数据库
   - 添加邮件
   - 修复 bug
   - 优化性能
```

**为什么错误**:
- 上下文会混在一起
- Claude 会困惑
- 质量下降
- 难以恢复特定任务

**何时开新对话**:
- ✅ 开始新功能
- ✅ 切换到不相关任务
- ✅ 上下文超过 30%
- ✅ Claude 响应质量下降

---

### 技巧 2: 外部记忆文件

**核心概念**:
```
不要把所有东西都放在对话上下文中
使用文件持久化重要信息
```

**推荐文件**:

#### SCRATCHPAD.md
**用途**: 工作笔记、临时想法、进度追踪

**示例内容**:
```markdown
# 当前任务
- [ ] 实现用户认证
- [ ] 添加密码重置
- [x] 创建 User 模型

# 待办
- 需要添加邮件验证
- 考虑 OAuth 集成

# 坑点
- Redis 连接池大小需要调整
- Middleware 顺序很重要
```

#### plan.md
**用途**: 项目计划、架构决策、实现步骤

**示例内容**:
```markdown
# 认证系统计划

## 架构
- User Model (已有)
- Session Store (Redis, 24h TTL)
- Middleware (保护 /api/protected/*)

## 实现步骤
1. 设置 Redis 连接
2. 创建认证中间件
3. 实现 login endpoint
4. 实现 logout endpoint
5. 添加会话管理

## 权衡决策
- 选择 Redis 而非 JWT: 更好的会话控制
- 24h TTL: 平衡安全性和用户体验
```

**好处**:
- ✅ 跨会话持久化
- ✅ 明天继续 → 读取文件 → 立即恢复
- ✅ 不占用对话上下文
- ✅ 可以版本控制

**高级技巧**:
```
把这些文件放在项目层级顶部
→ 所有任务和功能都能访问
→ 形成项目知识库
```

---

### 技巧 3: 复制粘贴重置法（强大！）

**场景**: 上下文已经很大，但有重要信息需要保留

**步骤**:

#### 1. 复制重要内容
```
从终端复制:
- 关键代码片段
- 重要决策
- 错误消息
- 待办事项
```

#### 2. Compact 总结
```bash
/compact
```
- 获得对话的简洁总结
- 保留关键点

#### 3. 清空上下文
```bash
/clear
```
- 完全清空对话上下文
- 重置到零

#### 4. 粘贴回重要信息
```
粘贴:
- 步骤 1 的重要内容
- Compact 的总结
- 当前任务描述
```

**结果**:
```
✅ 全新上下文（质量恢复）
✅ 保留关键信息
✅ 可以继续工作
```

**何时使用**:
- 上下文 > 40%
- 质量明显下降
- 对话很长但只需要部分信息
- 准备进入新的实现阶段

---

### 技巧 4: 知道何时清空

**清空的时机**:

#### 信号 1: 质量下降
```
Claude 的回答变得:
- 重复
- 不相关
- 缺少之前有的深度
- 忽略之前的上下文
```

#### 信号 2: 对话跑偏
```
原本: 构建认证系统
现在: 讨论 UI 颜色、数据库优化、部署策略
→ 完全跑偏了
```

#### 信号 3: 累积无关上下文
```
大量:
- 错误消息（已解决的）
- 调试输出
- 尝试过但放弃的方法
- 不相关的讨论
```

#### 信号 4: 上下文 > 30-40%
```bash
/context  # 查看当前使用量

如果 > 30-40% → 考虑清空
```

**清空命令**:
```bash
/clear
```

**重要提醒**:
```
Claude 清空后仍然有:
✅ CLAUDE.md（项目配置）
✅ 外部记忆文件（SCRATCHPAD.md, plan.md）
✅ 不会丢失项目上下文

实际上:
9/10 次，清空比不清空更好
（反直觉但真实）
```

## MCP 上下文管理

**问题**: MCP 服务器会占用大量上下文

**示例**:
```
4 个 MCP 服务器 = 67,000 tokens
还没输入任何东西！
```

**解决方案**: Tool Search (2026 新功能)

### Tool Search

**是什么**:
- 动态按需加载工具
- 而不是预加载所有工具

**效果**:
```
之前: 51,000 tokens (MCP 工具定义)
之后: 8,500 tokens
减少: 46.9%（甚至高达 95%）
```

**如何启用**:
```bash
# 自动模式（默认）
# 当 MCP 工具超过上下文 10% 时自动启用
ENABLE_TOOL_SEARCH=auto claude

# 自定义阈值（5%）
ENABLE_TOOL_SEARCH=auto:5 claude

# 完全禁用
ENABLE_TOOL_SEARCH=false claude
```

**工作原理**:
1. MCP 工具延迟加载（不预加载）
2. Claude 需要时搜索相关工具
3. 只加载实际需要的工具
4. 从用户角度看完全透明

**限制**:
- 需要 Sonnet 4+ 或 Opus 4+
- Haiku 不支持

## 会话管理

### 命令

```bash
# 恢复会话
claude --continue           # 继续最近的对话
claude --resume            # 打开会话选择器
claude --resume [name]     # 按名称恢复
claude --from-pr 123       # 恢复 PR 相关会话

# 会话内切换
/resume                    # 切换到其他对话
```

### 会话组织

**最佳实践**:
```
给会话起描述性名称
→ 方便以后查找

示例:
❌ "新对话"
❌ "工作"
✅ "用户认证实现"
✅ "数据库重构-用户表"
✅ "Bug修复-邮件发送"
```

**重命名会话**:
```bash
/resume
# 导航到会话
# 按 R 键重命名
```

## Compact 命令详解

**用途**: 总结当前对话，减少上下文

```bash
/compact
```

**产生的效果**:
- 生成对话的简洁总结
- 保留关键决策和代码
- 减少上下文使用

**何时使用**:
- 对话变长但想继续
- 在使用 /clear 之前
- 定期总结进度

**限制**:
```
⚠️ Compacting 不能恢复已降级的质量

如果质量已经在 30% 时降级
Compacting 只是总结低质量的内容
不会让质量回到原来
```

**最佳实践**:
```
在质量降级前 compact
不是在质量降级后
```

## 检查上下文使用

```bash
/context
```

**显示**:
- 当前上下文使用量
- Tokens 计数
- 百分比

**行动阈值**:
```
< 20%  : 安全，继续
20-30% : 注意，开始规划清理
30-40% : 警告，准备 compact 或 clear
> 40%  : 危险，立即采取行动
```

## 工作流示例

### 场景 1: 长期功能开发

**第 1 天**:
```
1. 创建 plan.md（功能计划）
2. 开始实现
3. 更新 SCRATCHPAD.md（进度）
4. 上下文 < 30%，继续
```

**第 2 天**:
```
1. 读取 plan.md 和 SCRATCHPAD.md
2. 新对话恢复上下文
3. 继续实现
4. 上下文 > 30% → Compact
```

**第 3 天**:
```
1. 上下文累积太多
2. 复制粘贴重置法:
   - 复制关键内容
   - /compact
   - /clear
   - 粘贴回来
3. 继续实现
```

### 场景 2: 调试会话

**开始**:
```
描述问题 + 错误消息
Claude 分析并建议修复
```

**中途**:
```
累积了大量:
- 错误输出
- 尝试的修复（失败的）
- 调试日志

上下文 > 40%
```

**清理**:
```
1. 问题已定位
2. /compact 总结发现
3. /clear 清空
4. 粘贴总结 + 继续实现修复
```

### 场景 3: 多任务切换

**错误做法**:
```
❌ 一个对话:
   任务 A → 任务 B → 任务 A → 任务 C
   上下文混乱，质量下降
```

**正确做法**:
```
✅ 对话 1: 任务 A（完成或暂停）
✅ 对话 2: 任务 B（完成或暂停）
✅ /resume 对话 1: 继续任务 A
✅ 对话 3: 任务 C

每个对话独立、清晰
```

- [ ] 这个任务需要新对话吗？
- [ ] 创建/更新外部记忆文件了吗？

- [ ] 定期检查上下文使用（/context）
- [ ] 上下文 > 30% 了吗？
- [ ] 质量有下降吗？
- [ ] 累积了很多无关内容吗？

### 质量下降时:
- [ ] 尝试 compact 了吗？
- [ ] 考虑复制粘贴重置了吗？
- [ ] 是否应该开新对话？
- [ ] 外部文件更新了吗？

### 任务完成后:
- [ ] 重要决策记录到 plan.md 了吗？
- [ ] SCRATCHPAD.md 更新了吗？
- [ ] 是否需要 /clear 为下个任务腾出空间？

## 常见错误

### 错误 1: 等到 100% 才管理
```
❌ "还有空间，继续加"
✅ "30% 了，开始规划"
```

### 错误 2: 过度依赖 Compact
```
❌ "质量降级了，compact 应该能修复"
✅ "质量降级了，需要 clear 重置"
```

### 错误 3: 一个对话做所有事
```
❌ 认证 + 数据库 + UI + 部署 = 一个对话
✅ 每个功能一个独立对话
```

### 错误 4: 不使用外部记忆
```
❌ 所有信息都在对话中
✅ 计划和进度在文件中
```

### 错误 5: 忘记 CLAUDE.md 还在
```
❌ "Clear 会丢失所有项目上下文"
✅ "Clear 重置对话，CLAUDE.md 保留项目配置"
```

## 高级技巧

### 技巧 1: 层级化的外部记忆
```
项目根目录/
├── CLAUDE.md           # 项目级配置
├── plan.md             # 总体计划
├── SCRATCHPAD.md       # 全局笔记
└── features/
    ├── auth/
    │   ├── plan.md     # 认证功能计划
    │   └── notes.md    # 认证笔记
    └── api/
        ├── plan.md     # API 计划
        └── notes.md    # API 笔记
```

### 技巧 2: 定期 Checkpoint
```
每完成一个重要里程碑:
1. /compact
2. 保存总结到文件
3. /clear
4. 从干净状态开始下一阶段
```

### 技巧 3: 主动预防
```
不要等质量降级
在上下文 20-30% 时就开始规划清理
```

## 关键提醒

1. **30% 是新的 100%**
   - 质量在 20-40% 开始降级
   - 不要等到 100%

2. **外部记忆是你的朋友**
   - plan.md, SCRATCHPAD.md
   - 跨会话持久化

3. **复制粘贴重置法很强大**
   - 复制 → Compact → Clear → 粘贴
   - 重置质量的最佳方法

4. **9/10 次 Clear 更好**
   - 不要害怕清空
   - CLAUDE.md 还在

5. **作用域你的对话**
   - 一个对话 = 一个任务
   - 不要混合不相关的东西
