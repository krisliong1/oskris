## 付款流程

### 标准三段式

```
签约 → 50% 定金 → 设计稿确认 → 30% 中期款 → 交付上线 → 20% 尾款
```

| 阶段 | 比例 | 触发条件 | 交付物 |
|------|------|---------|--------|
| 定金 | 50% | 合同签署 | 项目启动、开始设计 |
| 中期款 | 30% | 设计稿确认 | 完成开发、内部测试 |
| 尾款 | 20% | 网站上线 | 域名部署、交付源码 |

### 小型项目（< RM 3,000）

```
签约 → 50% 定金 → 交付上线 → 50% 尾款
```

## 发票模板

### 与报价单的区别
- 报价单 (Quotation): 签约前，可协商
- 发票 (Invoice): 确认项目后，正式收款凭据
- 收据 (Receipt): 收到款项后，确认收款

### 发票编号
```
INV-[年份]-[序号]
INV-2026-0001
```

### 发票需额外包含
- 付款截止日期（通常签约后 7 天内付定金）
- 已付金额 / 待付金额
- 逾期条款（逾期 30 天后项目暂停）

```markdown
| DEF  | 商城 | 9,999 | ✅ 5,000 | ✅ 3,000 | ⏳ 1,999 | 待交付 |
```

### 状态标记
- ⬜ 未开始
- ⏳ 待收款（已开发票）
- ✅ 已收款
- ⚠️ 逾期
- ❌ 取消

## 自动化工作流

### 创建报价单
```
用户说: "给 [客户名] 做个报价，专业版"
Claude 执行:
1. 读取此 Skill 的定价体系
2. 读取 oskris-brand-guidelines 获取品牌样式
3. 使用 pdf 或 docx Skill 生成专业报价单
4. 自动填入编号、日期、价格明细
5. 输出到 /mnt/user-data/outputs/
6. 存档到 GitHub: clients/[客户名]/quotation/
```

### 创建发票
```
用户说: "客户确认了，开发票"
Claude 执行:
1. 基于已有报价单生成发票
2. 添加付款截止日期
3. 输出 PDF
4. 存档到 GitHub: clients/[客户名]/invoice/
```

### 收款确认
```
用户说: "收到 ABC 的定金了"
Claude 执行:
1. 更新项目收款状态
2. 生成收据 PDF
3. 更新记忆中的项目进度
4. 存档到 GitHub: clients/[客户名]/receipt/
```

## 马来西亚税务注意事项

- **SST (Sales and Service Tax)**: 年营业额超过 RM 500,000 需注册
- **个人所得税**: 自由职业/个体户需申报
- **发票要求**: 无需 SST 号码（除非已注册），但建议包含公司注册号（如有）
- **电子发票 (e-Invoice)**: 马来西亚 2025 年起逐步推行，年营业额 > RM 25M 的需使用，小企业暂不强制
