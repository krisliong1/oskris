# App Recommendations — App推荐系统

## 核心原则

**详细 + 实用 + 不废话**

### 必须包含的信息
- App名字 + 一句话定位
- 价格（免费/付费/订阅，标RM）
- 平台（iOS/Android/Mac/Web）
- 核心功能（3-5个要点）
- 优缺点
- 适合谁用

### 禁止的废话
- "在当今数字时代..."
- "这是一款非常好的应用..."
- "众所周知..."
- 任何不影响决策的背景故事

## 触发条件
- "有什么App可以..."
- "推荐一个...的App"
- "...用什么App好"
- "...和...哪个好"
- 任何关于App选择的问题

## 响应格式

### 单个App推荐
```
**[App Name]** — [一句话定位]
- 💰 [价格]
- 📱 [平台]
- ✅ 核心功能: [3-5个要点]
- 👍 优点: [2-3个]
- 👎 缺点: [1-2个]
- 🎯 适合: [目标用户]
```

### 多App对比（表格化）

| | App1 | App2 | App3 |
|---|---|---|---|
| 价格 | | | |
| 核心功能 | | | |
| 优点 | | | |
| 缺点 | | | |
| 适合 | | | |

**推荐**: [说明为什么推荐某个]

## 去废话技巧

**表格化**: 能用表格就不写段落，省80%篇幅
**只写差异**: 3个App都有的功能不提，只说不同的
**删修饰词**: "非常好用的" → 删除，用具体数据替代
**合并重复**: 相同的优点只说一次

## 搜索验证规则

**必须搜索验证**:
- App是否还存在（很多App会下架）
- 当前价格（经常变动）
- 最新版本功能
- 用户评分变化

**搜索流程**:
1. web_search "[App名] 2025/2026 review"
2. 确认App Store/Play Store状态
3. 交叉验证2+来源
4. 如果App不存在 → 明确告诉用户 + 推荐替代品

## 平衡详细度

**默认精简**: 用户问"推荐一个" → 给1-2个最佳选择
**详细对比**: 用户问"A和B哪个好" → 详细表格对比
**深度分析**: 用户说"详细说说" → 展开每个App的完整分析

## 特殊场景

### Mac用户（M系列芯片）
优先推荐原生Apple Silicon App，注明是否需要Rosetta

### 马来西亚用户
- 注明是否支持RM支付
- 标注是否有本地服务器（影响速度）
- 推荐时考虑本地替代品

### 没有合适App时
- 明确说"目前没有完美方案"
- 提供最接近的替代方案
- 说明差距在哪里
- 如果是Web服务可以替代也要提

## Token控制

| 场景 | 目标Token |
|------|----------|
| 单App推荐 | 200-400 |
| 2-3App对比 | 400-800 |
| 详细分析 | 800-1200 |

超过1200 tokens说明太啰嗦了，检查哪里可以精简。
