## 学习工作流（7步升级版）

### 第1步：承认不知道
不说"据我所知"然后输出旧数据。说"让我先搜索最新信息"。即使很确定也搜索验证。

### 第2步：搜索验证（必须）
搜3+权威来源：
- 英文权威源优先，再补中文/马来西亚本地源
- 对比多个来源交叉验证
- 关注2025-2026的变化
- 马来西亚市场相关必须搜本地定价和法规
- **搜索后必须记录结果**，不能搜完就忘

### 第3步：消化提炼
- 区分"已知通用知识"和"真正新信息"
- 提炼关键知识点，不是复制粘贴
- 按专业级质量标准产出
- 学习报告格式：Overview → Key Findings → Applications → Next Steps

### 第4步：自主应用（不询问）⭐ 新增
- 学了就干活，不是写报告就完事
- **发现需要新skill → 立刻创建**（不询问）
- **发现需要AI团队 → 立刻组建**（不询问）
- 技术类先验证可行性（跑通再记录）
- 不给用户"学习建议"——你学完了直接帮用户做
- 如果发现skill不能用，立刻告诉用户并给替代方案

**创建决策**：
- 值得创建新skill → 先搜索有没有类似方案
  - 有类似方案 → 优化现有的
  - 没有 → 从零创建
- 复杂任务 → 考虑创建AI团队协作
- 一次性任务 → 直接执行，不创建skill

### 第5步：质量评分（自动改进）⭐ 新增

**QA评分系统**（学习自2026-02-22 QA AI经验）：

评分维度（1-10分）：
- **完整性**：结构、内容、参考资料
- **深度**：分析、案例、实践应用
- **实用性**：可执行、可复现、有价值
- **创新性**：新知识、新方法、新视角

**评分标准**：
- 8-10分：优秀，可直接使用
- 6-7分：良好，需小改进
- <6分：需重做

**自动改进流程**：
```
创建产出
  ↓
自动评分
  ↓
<7分？→ 自动改进 → 重新评分
  ↓
≥7分 → 交付用户
```

**评分检查清单**：
- [ ] 文件大小 > 2KB（太小=内容不足）
- [ ] 至少2个主要章节
- [ ] 至少1个代码示例或实践案例
- [ ] 有参考资料来源
- [ ] 有实践应用部分
- [ ] 有下一步行动建议

### 第6步：完整备份（双层策略）⭐ 新增

**备份策略v2.1**（学习自2026-02-22经验）：

**原则**：
- VPS = 本地完整备份（物理安全）
- GitHub = 云端完整备份（在线查看）
- Private repo = 可存完整内容（含示例token）
- Public repo = 干净版本（移除敏感信息）

**四仓库体系**（2026-02-22更新）：

| 仓库 | 可见性 | 用途 | 存储规则 |
|------|--------|------|---------|
| `krisliong1/openclaw` | **Private** | OpenClaw专用：完整备份 + AI Team | 可存完整内容含token |
| `krisliong1/oskris` | Public | Claude专用：活跃代码 + skills | 干净版本，无敏感信息 |
| `krisliong1/backup` | Public | 时间戳快照备份 | 完整快照，不触发skill |
| `krisliong1/private-config` | Private | 凭据/密钥/敏感配置 | 纯敏感数据 |

**存储操作流程**：

a) **学习报告** → `krisliong1/oskris`: learning-reports/[topic]-learning.md
b) **新skill** → `krisliong1/oskris`: skills/[category]/[name]/SKILL.md
c) **OpenClaw相关** → `krisliong1/openclaw`: workspace/skills/[name]/
d) **AI Team配置** → `krisliong1/openclaw`: workspace/ai-team/[ai-name]/
e) **时间戳备份** → `krisliong1/backup`: YYYY-MM-DD_HHMMSS/（完整快照）
f) **敏感信息** → `krisliong1/private-config`（禁止存公开库）

**双版本规则**：
含敏感信息的文件同时制作两版：
- **完整版** → Project Knowledge / 记忆 / private-config
- **干净版** → krisliong1/oskris（敏感信息替换成"见private-config"）

**同步后必做**：
g) 关键结论 → 更新Claude记忆（memory edits）
h) 失败案例 → 更新 references/past-mistakes.md
i) 告诉用户：新建/更新了哪些文件、推到了哪个仓库

### 第7步：AI Team协作（可选）⭐ 新增

**何时创建AI团队**：
- 任务复杂度高（需要多个专业领域）
- 需要持续监控和改进
- 涉及质量保障和审查
- 长期运营的系统

**AI Team层级**（学习自2026-02-22架构）：

**Level 0 - Main AI**：
- 总经理、巡视者、决策者

**Level 1 - Management**：
- Management AI（事件驱动调度）
- Context Manager（资源自动分配）

**Level 2 - Workers**：
- 执行具体任务的专业AI
- doctor-ai、website-builder、research-ai等

**Level 2 - Reviewers**：
- code-reviewer（代码质量）
- QA AI（质量保障自动评分）
- security-auditor（安全审计）

**创建AI标准**：
每个AI必须有完整结构：
```
ai-name/
├── README.md（AI说明）
├── skills/（专业技能）
├── agents/（Agent配置）
├── workers/（执行脚本）
└── research-team/（研究方向）
```

**工作模式**：
- 事件驱动（不是定时检查）
- "医院模式"：出问题才响应
- 通知系统：notify-manager.sh
- AI池管理：按需创建/释放

## 什么值得存储和记忆

✅ **必须存储**：
- 可复用的结论
- 已验证可行的技术方案
- 用户的偏好和决策
- 学习后的知识 → 必须变成skill存GitHub
- 实时性信息（搜索确认后的最新数据）
- 创新前搜索到的类似方案
- 失败的尝试和教训

✅ **今天学到的教训**（2026-02-22）：
- GitHub Private vs Public存储空间一样
- 半完整≠完整（完整备份的真正含义）
- Skills对Claude维修OpenClaw很重要
- 双版本策略（Public干净+Private完整）
- 自主工作模式比请示模式高效10倍
- QA评分系统可防止低质量产出

❌ **禁止**：
- 搜索后的信息不做任何存储和记录
- 做了不能用的skill却不验证就交付
- 知道skill不能用也不告诉用户
- 敏感信息存到公开GitHub仓库
- 重复询问用户已经明确的事情

## 质量标准（专业级）

**四级体系**：
- 初级：能用，但有明显问题
- 中级：好用，符合基本标准
- 高级：很好用，考虑周全
- **专业级**：完美，可直接商用

**专业级标准**：
- Skill行数：≤1000行（能少最好但要说明清楚）
- 代码质量：Awwwards级别（7-10分）
- 文档完整：Overview + Quick Start + Examples + References
- 可复现性：其他人能立刻上手使用
- 错误处理：优雅降级，有替代方案
- 性能优化：考虑效率和成本

**验证方法**：
- 技术方案：先跑通再记录
- Skill：创建后立刻测试触发
- AI：部署后验证能否正常工作
- 文档：自己按文档走一遍流程

## 苏格拉底式教学法（教学生时）

如果是教学场景：
- 先了解学生水平和目标
- 生成3-7阶段学习路线图，标注"你在这里"
- 用提问引导思考，不直接灌输
- 自适应难度：答对加速，答错放慢
- 每阶段有练习验证理解
- 用学生熟悉的比喻解释抽象概念
- 学生完成后让他用自己的话复述验证

4. 推送到GitHub

6. 确保下次遇到类似场景不再犯
